# Flagship blog draft admission

Existing grant versions 1 and 2 retain their published behavior. Version 3 requires an explicit `publicationMode` on every target and an `expiresAt` on every grant, in canonical UTC ISO format including milliseconds (`YYYY-MM-DDTHH:mm:ss.sssZ`). Missing, invalid or noncanonical expiry fails closed. The matching credential is rejected at or after its deadline on create, archive and lookup, before database access; an expired well-formed grant does not disable a different active grant. Version 1 and 2 semantics remain unchanged. A draft grant permits only blog POST and archive PATCH for `default/en`; draft PUT and other content types are rejected during grant parsing. A separate credential with only these two targets must be used for draft acceptance.

POST retains the existing validated engine payload, including its requested `published` status, but the credential forces storage as `draft`. The response states `status: draft`, `requiresManualPublish: true`, `id`, `slug`, and `publishReceiptId`. It has no public URL. Draft creation skips storefront invalidation; the model's existing published-only hook excludes it from search indexing. The Content Engine already stores this result as `needs-review` without a publication outbox, webhooks, or IndexNow. All automation remains independently disabled.

Cleanup uses `PATCH /api/admin/content/blog/archive` with the same target headers and the dedicated archive grant. Its body contains `id`, `publishReceiptId`, `tenantId`, `defaultLocale`, and `expectedRevision` (from the authenticated slug lookup). Send a fresh UUID `Idempotency-Key` for the archive operation. The atomic update requires the exact grant, publication receipt, tenant, unchanged revision, draft status, and no pending update marker. It stores `archivedAt` and an operation/input fingerprint while retaining the complete draft. Identical archive replay returns `archived`; changed input or state conflicts. Failure before acknowledgment is safely retryable.

Archived records remain private drafts and retain their natural key and provenance. Creation replay reports `archived`; a fresh creation cannot reuse the slug; receiver PUT cannot publish it. Ordinary admin updates cannot clear the archive or replace provenance, and increment the revision to fence concurrent archive attempts. Recovery is deliberate operator work from the retained record; this contract has no restore or promotion operation. Never use the general admin DELETE route for acceptance cleanup.

Before activation, verify the exact release, receiver indexes, independent backup, credential boundary, Content draft handling, and zero publication effects. A public article still requires a separately chosen article and publication grant; this draft grant never authorizes it.

Expiry bounds validity across older deployments retaining the same environment; it does not provide immediate revocation. Freeze a short absolute deadline once for the acceptance operation and never extend it automatically on retry. Configuration removal alone is not proof that immutable prior deployment URLs reject a credential. Complete or deliberately recover cleanup before expiry; after expiry, the same key cannot archive or inspect the retained draft.
